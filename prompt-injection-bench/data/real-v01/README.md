## 来源、证据与许可

`split-plan.json` 先分配出版物家族，再编写 `annotations.json`。同一出版物的修订、译本和同家族配套部分必须沿用该家族的分组。当前每个家族只有一个版本，不能把同一文档的段落随机分进两组。

`sources.json` 保存官方落地页、PDF地址、DOI、版本、获取时间、PDF SHA-256、提取器版本和许可依据。`source-pages/` 保存选中页的空白归一化文本与 SHA-256；每题保存物理 PDF 页码（从1开始）、章节、字符起止位置、原文证据、答案和预先登记的等价答案。页码不是书内印刷页码。PDF原文件在本地 `runs/real-source-pdfs/` 缓存，可从注册表中的地址重新获取并核验哈希。

采用 [NIST Technical Series 出版物使用政策](https://www.nist.gov/open/copyright-fair-use-and-licensing-statements-srd-data-software-and-technical-series-publications)，不宣称所有内容均为 CC0。政策区分美国政府作者作品、NIST持有的境外权利和第三方版权；本集引用NIST正文，不采集第三方插图或被引作品。原文出处以各条目题名、版本、DOI为准。

Republished courtesy of the National Institute of Standards and Technology.

原文只做空白归一化，保留PDF提取中的排版字符；问题、答案别名与实验附加指令由AI编写，不是NIST提供或认可的内容。材料按原样提供，无NIST背书。许可记录不是独立法律审查。

## 生成与检查

在项目目录运行：

```powershell
python scripts/build_real_dataset.py
python scripts/build_real_dataset.py --check
python -m unittest discover -s tests -v
```

离线生成器校验来源分组、证据定位、页面哈希、答案包含关系、重复知识目标与问题。它不是语义去重模型，仍需独立人员复核题意与证据充分性。`dataset.json` 为全集，`dev.json` 和 `test.json` 分别供实验使用；原合成数据保持独立。

若需重新取得PDF，安装 `pypdf==6.10.0` 后在项目目录执行 `python scripts/acquire_real_sources.py`（需要联网）。它只写入被忽略的 `runs/real-source-pdfs/`；新下载版本的哈希必须与 `sources.json` 比对，不能静默替换冻结数据。日常构建与实验不依赖pypdf。

分组确定后，每题生成12个条件：3个正常控制（普通、引用攻击句、证据内嵌引用）以及3种攻击模板×中文/英文/混合表达。开发集132个变体，测试集144个变体；变体不增加独立问题数。`*-variants.json` 保存父题、来源、分组及输入哈希，实际文本由现有 `bench.data.cases` 确定性生成。正常困难样本的引用句与攻击都是人工构造，不能当成源文档原话。

## 首次真实模型试跑

`pilot-dev.json` 在推理前固定选择认证最小长度、IaaS识别、策略引擎职责各一题，共3个来源。每模型：3题×12变体×3防御×1次重复＝108次调用。温度0，种子42；这只是流程与兼容性试跑，不是完整开发集结果。模型digest在冻结时记录，在运行前后检查。

## 边界与后续复核

- 来源真实，问题由AI根据文档编写；没有自然用户提问采样，也尚无独立双人人工标注。
- 测试集按来源留出，但文件公开且作者可见，不是秘密测试集；本次不对测试集推理。它复用已知攻击模板，不能声称未知攻击泛化。
- 全部来源属于NIST，中文问题配英文证据；主题与原校园合成集不同，不应混合统计或把差异归因于语言一个因素。
- 每组仅3个来源家族，数量不足以支持稳健的显著性或模型排名结论。`family` 使用来源家族，避免把同源问题当作独立来源。
- 当前评分为预先登记别名匹配及字面引用核验，不是语义蕴含判断。看过开发输出后增补别名必须另存评分版本，不覆盖已冻结结果。
- 下一轮优先拓展新的来源家族和任务类型（条件、例外、跨段关系），先审查许可和分组，再出题；不要仅扩充数字或术语题。
