# 候选防御：按句隔离与引用检查（D3）

目标：降低D2整段过滤造成的正常证据损失，并阻止无可追溯引文的回答直接交付。此方案是项目内的新候选实现，尚不主张学术首创，也不保证消除提示注入。

## 已有研究与定位

- [DataFilter](https://arxiv.org/abs/2510.19207)：训练过滤模型，结合用户指令与数据删除恶意指令并保留正常信息。本项目的选择性过滤方向与之重叠，不能把这个大方向称为原创。
- [Spotlighting](https://www.microsoft.com/en-us/research/publication/defending-against-indirect-prompt-injection-attacks-with-spotlighting/)：通过输入转换标明不可信来源。
- [StruQ](https://www.usenix.org/conference/usenixsecurity25/presentation/chen-sizhe)：结构化查询与专门训练，分离指令与数据。

我们尝试无需额外模型或训练的轻量组合，重点验证“对相同检测规则，改变删除粒度是否改善安全与正常任务表现的权衡”。尚未完成穷尽的新颖性检索。

## 算法

1. 输入只有用户问题、实际检索片段；不使用标准答案、证据标签、来源分组、攻击标记或变体标签。
2. 按换行、中英文句末标点划分片段。使用与D2完全相同的四条规则检测，不增加针对已知攻击模板的特例。
3. 隔离命中规则的局部句子，保留其余连续原文。记录原片段编号、字符偏移和规则；不把删除位置两侧的文字拼成虚构原文。
4. 保留内容交给原有带边界提示的问答模型。
5. 模型生成后，独立程序检查JSON结构和非空引文：引文必须是某个保留原文片段的连续子串。检查失败则交付 `UNKNOWN`，保留原始模型输出和拒绝原因。模型自行输出UNKNOWN时清空其引文。

运行时间由一次原有模型推理加文本扫描组成，不额外调用模型；没有测量能耗。分句与正则是启发式规则，不理解话语角色。

## 在真实推理前固定的开发试验

使用已有 `data/real-v01/pilot-dev.json` 中3题，每题12变体。它们及历史输出已被开发者看过，因此本次仅检验开发假设，不作为独立泛化证据。测试集不运行、不修改。

| 条件 | 含义 | 解释用途 |
|---|---|---|
| D2 | 原有整段删除、边界提示 | 基线 |
| D3S | 按句隔离、同一边界提示 | 单独检验删除粒度 |
| D3 | D3S再加输出引用检查 | 单独检验引用检查 |

Qwen3 8B，温度0、种子42、每条件一次，3×12×3＝108次真实调用。模型digest自动冻结并在运行前后核验；不要用旧日志充当本次基线。

假设H1：D3S减少clean_embedded正常证据损失并改善答案匹配；H2：D3阻止部分无有效原文引用的输出，但可能增加拒答。失败结果同样保留，不根据本轮结果修改规则或答案别名后重算原成绩。

## 已知失败边界

- 攻击与有效事实位于同一句、缩写或复杂排版可能导致误分句或整句证据丢失。
- 同义改写、跨句或隐含攻击可能绕过现有四条规则。
- 攻击者可提供一个原文中确实存在的引文，同时给出错误答案：引用检查不验证答案是否由引文支持，也不证明文档事实真实。
- 正常的攻击语句分析任务会受隔离影响；此实现不能解决所有正常困难样本。
- 格式错误或合理的引文改写也会被门控拒绝，可能造成效用损失。
- 三题、单模型、单次重复无法支持显著性或泛化结论。后续需要额外开发来源、语义改写、同句混合、正常安全分析样本以及独立人工复核。

新增代码后源代码哈希会变化，旧冻结锁在当前代码下应拒绝重跑。历史档案保留；复现旧实验需检出其对应提交，运行新实验需新建锁。
