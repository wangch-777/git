# 任务04交付：大文件统计、分页与导出

2026-09-14。仅修改后端、Worker、测试和性能测量工具；没有改动前端、接口路径、参数名或JSON结构。

## 字段与迁移

`detection_tasks`新增可空INTEGER字段`normal_count`、`attack_count`，不设置零默认值：NULL表示旧任务尚未计算，0表示已确认没有对应类别。检测Worker每块累计计数，在CSV临时文件成功替换为最终文件后，将计数、结果路径和成功状态在同一次数据库更新中保存。校验两类计数之和等于处理行数，不改变状态机。

`initialize_database()`现在统一按“表名→新增字段”处理实验表与检测表，缺列才ALTER TABLE。旧SQLite在检测字段迁移前保存`*-before-detection-counts.sqlite3`；原实验表独立迁移的备份名仍兼容。备份存在不覆盖，迁移可重复执行，旧任务计数保留NULL。

本机已生成`ids-before-detection-counts.sqlite3`并完成迁移。备份和运行数据不入Git。

## 查询方式

|接口|此前|现在|
|---|---|---|
|statistics|每次完整读取结果CSV并统计|有摘要直接按两类计数返回，完全不读取CSV；NULL时分块只读predicted_label，并持久化回填|
|results，无label|整表读入后切片|摘要提供total；nrows只构建当前页，用skiprows回调跳过前缀，避免构造大型跳行集合|
|results，有label|整表过滤、切片|摘要提供过滤total；每块10,000行扫描，只收集当前页，凑齐后停止读取|
|report，无label|完整DataFrame转成一个大字符串|StreamingResponse原样按64KiB拷贝已有CSV，保留原始字节|
|report，有label|完整DataFrame过滤后转成大字符串|每块10,000行过滤后输出；只写一次BOM和表头；零命中也有表头|

删除了`result_frame()`，避免未来误用整表加载。文件列名、顺序、UTF-8 BOM、附件名称`detection-{id}-{all或label}.csv`均保持兼容。成功任务已有摘要时，即便结果文件后来缺失，统计仍可展示历史计数；明细和下载仍返回410。未完成任务仍返回409。

空筛选的attack_ratio为0；label=1时仅攻击计数，label=0时仅正常计数。计数字段属于内部实现，未新增到现有检测状态响应JSON。

## 实测

合成CSV使用与Worker一致的4列，每3行一条攻击，中文预测名称，score=0.875；分别50,000和300,000行。旧版逻辑在基准工具中保留作对照。每种操作运行3个独立子进程，取中位数；页大小20。最后一页分别按全局/筛选总数计算。

时间包含查询函数及CSV解析/序列化，排除Python启动、生成数据、SQL查询及HTTP传输；摘要统计项测的是取得两个整数后的计算成本，不是实际HTTP延迟。内存为tracemalloc记录的Python分配峰值，不是进程RSS，不涵盖所有原生库分配。操作系统文件缓存、tracemalloc开销会影响时间，不能把这些数字当作生产服务吞吐保证。

结论：统计、首页和完整导出明显降低时间与内存；末页、筛选末页、筛选导出降低内存，但本次耗时略增或约翻倍，不能宣称所有操作都加速。CSV没有行偏移索引：skiprows仍需要扫描前缀，末页时间仍为O(N)，不是O(page_size)。无过滤分页内存为页数据加解析器缓冲；有过滤分页/导出为固定10,000行块加页数据，不是严格只有20行占用，但不再随整表行数线性增长。本任务未引入索引数据库，符合30万行范围内的改造目标。

首次查询旧任务需要一次O(N)分块回填，后续统计无需CSV；首次旧任务分页可能先回填再扫描所需页。并发首次回填可重复计算，但对不可变的成功结果写入相同计数。
