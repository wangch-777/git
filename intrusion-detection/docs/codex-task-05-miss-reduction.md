# 任务05：降低误报与漏报（标签冲突清理 + 概率校准 + 成本敏感阈值）

> 面向 Codex 的 ML/后端任务。前端对接遵循 `docs/frontend-backend-contract.md`；
> 本项目分工：Codex 负责后端/ML/Worker，TraeWorkCN 负责前端。

## 一、背景与已确认事实

- 基线（随机森林，固定阈值 0.5）：完整原测试集上 **正常流量误报率 FPR=16.07%**、攻击召回 96.77%（即漏报率 3.23%）、Accuracy 91.00%、AP 98.8%。
- 已完成的「阈值实验」（`docs/error-diagnostics.md`）证实：把验证阈值从 0.5 抬到 0.7，误报正常样本 549→194，但漏报攻击样本 1,301→2,456。**这是误报↔漏报此消彼长的权衡，不是模型变差。**
- 任务02的去重实验（`docs/experiment-quality.md`）证实：简单 `keep=first` 去重后，测试误报率反而从 16.07% 升到 30.38%。说明标签冲突未妥善处理是根因之一，单纯的去重方向错了。

本任务的目的是：**在不“刷测试集”的前提下，把误报与漏报同时压低**，而不是继续靠调阈值做交换。

## 二、四个根因（按优先级，均已从数据得到证据）

1. **标签冲突 + 重复记录**：训练源 74,301 条重复特征记录，其中 229 组「特征完全相同但标签不同」；`keep=first` 武断保留首个标签，把互相矛盾的样本喂给模型，迫使决策边界穿过冲突点，导致分数在这些区域不可校准。
2. **概率不校准 + 固定 0.5 阈值**：随机森林的 `score` 不是真实 P(攻击)，固定阈值 0.5 对不到目标工作点，阈值一提漏报立刻上升。
3. **类别先验漂移**：训练集攻击占 68.05%，测试集只占 55.06%；模型按 68% 的攻击先验校准，到测试集上过度偏向「攻击」，于是漏报偏低、误报偏高。
4. **评价集非独立**：测试集有 8,541 条特征与训练集重叠，边界信息泄漏，测试成绩偏乐观。

## 三、任务目标

在当前数据与特征约束下，得到一个可复现、可解释的方案，使**完整原测试集**上的误报率下降，同时漏报率不劣于基线；并明确报告在多「成本比」下可选的阈值工作点。

## 四、执行步骤（每步独立验证，禁止用测试集回看选参）

### S1 标签冲突的妥善处理（治本，最高优先级）
- 对训练源按 42 个输入特征（不含 id/label/attack_cat）哈希分组，标记冲突组（同特征、不同标签）。
- **不要用 `keep=first`**；至少对比三种策略并如实报告：
  1. 丢弃所有冲突组；
  2. 按组内多数标签裁决，只丢弃少数侧样本；
  3. （对照）`keep=first`。
- 去重/清洗后，用 `GroupShuffleSplit(seed=42, test_size=0.2)` 重训，只在验证集选参。
- 记录每组策略的 removed/conflict 数量，以及验证、完整测试的误报率/漏报率/召回/F1/AP。

### S2 概率校准 + 按成本选阈值
- 在验证集分数上做 Platt Scaling（或 Isotonic），输入端必须是训练时未见过的验证样本分数。
- 校准后按「漏报代价 : 误报代价」选工作点，提供并报告至少 1:1、5:1、10:1 三档。
- 校准映射器与所选阈值写入模型包（若结构变化需同步 `ml/registry.py`、`worker`、检测链路），并保留 0.5 作为对照。

### S3 类别先验对齐
- 训练期按目标部署场景先验调整：对比 `balanced`、目标先验（约 55/45）、默认三类。
- 三类均在验证集选参后，报告完整测试指标，不挑测试。

### S4 独立无泄漏评价协议
- 构建真正独立的「非重叠测试子集」：去掉测试中与训练特征重叠的 8,541 条样本，作为诊断指标。
- 最终成绩仍以**完整原测试集**报告（保持与历史可比）；非重叠子集仅作诊断，不宣传为泛化上界。
- 明确写死：任何选参只允许发生一次，且只依据验证集；测试集只用于最终报告一次。

## 五、约束（必须遵守）

- 不修改「完整原测试集固定阈值成绩」的历史口径与复现路径，新增方案只能作为附加协议并存。
- 每个方案必须可复现：文档里写清命令、参数、随机种子、数据摘要。
- 负结果也必须如实写入（区分「模型上限」「数据/特征约束」与「方法错误」）。
- 若模型包字段或对外接口发生变化，需同步更新 `docs/frontend-backend-contract.md`，若前端需新字段则一并写入 `docs/frontend-api-requests.md`。

## 六、交付物

1. 代码：数据清理、校准、成本阈值、评价协议（`ml/` 与 `worker/` 相应改动）。
2. 报告 `docs/miss-reduction.md`：S1–S4 的方案、参数、验证指标；最终「固定 0.5 vs 校准成本阈值」在完整测试集上的误报率/漏报率/召回/F1/AP 对比表；最终选用方案及理由；无法进一步下降的诚实边界。
3. 测试：新增 pytest（校准、冲突清理、阈值边界、评价协议），并保证既有测试不回归。
4. 文档同步（如有接口/字段变化）。

## 七、验收标准

1. 选参全程只在验证集；测试集只用于最终一次报告。
2. 报告完整「误报↔漏报」前沿，并给出在「漏报率不高于基线（≤3.23%）」约束下能达到的**最低误报率**，作为推荐工作点。
3. S1 的三种冲突策略中，至少一种在完整测试集上「误报率下降 且 漏报率不升高于基线」，或给出无法同时改善的、可复现的证据与原因。
4. 全部测试通过；不影响前端既有构建与功能。
